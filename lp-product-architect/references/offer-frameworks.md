# Offer Construction Frameworks

## Core Principle

The offer is NOT the product. The offer is: product + guarantee + urgency + bonuses + anchoring,
packaged to make saying "yes" feel safer than saying "no."

---

## 1. Guarantee Patterns

Match guarantee to LP type and risk level:

### Results-Based Guarantee (High trust, high confidence)
```
"If [specific measurable outcome] doesn't happen within [timeframe],
we [refund/pay you/redo for free]. No questions."
```
**Best for:** Service sales, agencies, consultancies
**Example:** "If your AI system doesn't reduce costs by 40%+ in 90 days, full refund."

### Time-Based Money-Back (Standard, low risk)
```
"Try it for [7/15/30] days. If it's not for you, get a complete refund."
```
**Best for:** Direct product sales, SaaS, courses

### Value-Keep Guarantee (for free offers / consultations)
```
"Keep the [deliverable] even if you decide not to work with us."
```
**Best for:** Service bookings, lead magnets, consultations
**Example:** "Book your AI ROI Analysis — keep the full report either way."

### Improvement Guarantee (Performance-based)
```
"If we don't beat your current [metric] by [amount], you don't pay."
```
**Best for:** Performance marketing, optimization services

### No Guarantee (Authority positioning)
```
Skip the guarantee. Instead, use: "We have [X] clients. Here's what they say."
```
**Best for:** Portfolio pages, premium/luxury positioning, waitlists

**Selection rule:** Use the STRONGEST guarantee the client is comfortable with.
Stronger guarantee = higher conversion. Challenge the client if their guarantee is weak.

## 2. Price Anchoring Patterns

Make the price feel small by comparison:

### Enterprise Comparison
```
"Enterprise consultancies charge $[high amount] for [longer timeline].
We deliver [same/similar result] in [shorter time] for $[lower price]."
```

### Cost of Inaction
```
"You're currently losing $[amount] per [month/year] to [problem].
Our solution costs $[price] — it pays for itself in [short timeframe]."
```

### Hourly Breakdown
```
"At $[price] over [months], that's $[daily amount] per day —
less than [relatable comparison: a coffee, a lunch, a parking spot]."
```

### ROI Calculation
```
"Investment: $[price]. Expected return: $[amount] in [timeframe].
That's [X]x ROI."
```

### Alternative Comparison
```
"Hiring a full-time [role] costs $[salary + benefits].
Our [solution] delivers [same output] for [fraction] of that cost."
```

**Selection rule:** Use the anchor that creates the biggest contrast. Always use REAL numbers.

## 3. Urgency & Scarcity Patterns

Only use REAL urgency. Fake countdowns destroy credibility.

### Capacity-Based (Real)
```
"We take on [X] new clients per [month/quarter].
[Y] spots currently available."
```
**Works when:** Team is genuinely small and capacity-limited.

### Seasonal/Timing (Real)
```
"[Event/season] starts [date] — projects need [X weeks] to deploy.
Start now or wait until [next window]."
```
**Works when:** There's a genuine deadline tied to external events.

### Price Increase (Real)
```
"Current pricing: $[price]. After [date/milestone]: $[higher price].
We're raising prices as demand grows."
```
**Works when:** Business is genuinely growing and pricing is increasing.

### Cohort-Based (Real)
```
"Next cohort starts [date]. Only [X] seats.
Missed this one? Next cohort is [later date]."
```
**Works when:** Delivering in batches/groups.

### Social Proof Urgency
```
"[X] people viewed this page today. [Y] booked calls this week."
```
**Works when:** You have real traffic data. Never fabricate.

**NEVER use:**
- Fake countdown timers that reset
- "Only 3 left!" when unlimited
- "Offer expires tonight!" when it doesn't

## 4. Objection Handling Framework

For each of the top 5 objections, prepare:

```
OBJECTION: "[What the prospect says]"

REFRAME: [Change how they see the objection]
EVIDENCE: [Proof that overcomes it — testimonial, data, case study]
CTA: [Micro-action to move forward despite the objection]
```

### Common Universal Objections

| Objection | Reframe Pattern |
|-----------|----------------|
| "Too expensive" | Anchor against higher alternative + ROI calculation |
| "Not the right time" | Calculate cost of waiting / cost of inaction |
| "I need to think about it" | Offer zero-risk trial or guarantee |
| "I'm not sure it works for my case" | Specific case study matching their situation |
| "I've tried something similar before" | Explain mechanism difference + why yours is different |

## 5. Bonus Stack (for Direct Sales)

If selling a product/course/service package, bonuses increase perceived value:

```
CORE PRODUCT: [Name] — Value: $[anchor price]

BONUS 1: [Name] — Value: $[amount]
(Choose something that REDUCES TIME to result)

BONUS 2: [Name] — Value: $[amount]
(Choose something that REMOVES a common obstacle)

BONUS 3: [Name] — Value: $[amount]
(Choose something with HIGH perceived value, low delivery cost)

TOTAL VALUE: $[sum of all anchors]
YOUR PRICE: $[actual price]
```

**Rules for good bonuses:**
- Each bonus should solve a specific sub-problem
- Don't add bonuses just for stack height — each must have clear value
- At least one bonus should be deliverable IMMEDIATELY (instant gratification)
- Name bonuses as standalone products, not generic additions
